# dsh-cat-pet

Анимированный котик-компаньон («Pet») для веб-интерфейса
[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness).

Кошка живёт поверх интерфейса: её можно перетаскивать, она помнит позицию и
реагирует на то, чем занят агент. Пока агент думает — ложится и засыпает;
если в сессии ничего не происходит — тоже укладывается спать. На ваш ход или
на начало печати в поле ввода — встаёт и садится.

Плагин состоит из хост-части на Cordis (намеренно пустой, см. ниже) и
браузерной части в слоте `shell.overlay`.

## Состояния

Набор простой и «бытовой»: это не статус агента напрямую, а то, чем занята
кошка.

| Состояние | Анимация | Когда показывается |
| --- | --- | --- |
| `sit` | сидит | По умолчанию: короткий ход, ход завершён, ожидание решения, ошибка, идёт печать |
| `lie` | ложится | Переход `sit → sleep`, проигрывается один раз |
| `sleep` | спит | Агент думает дольше 10 секунд **или** в сессии больше минуты ничего не происходит |
| `wake` | встаёт | Переход `sleep → sit`, проигрывается один раз |

Логика привязана к тому, что **видно на экране**, а не к бездействию окна:

```
агент думает ≥ 10 с     →  sit → lie → sleep   (ждёт вместе с тобой)
минуту ничего не было   →  sit → lie → sleep   (заскучала и улеглась)
ход перешёл к тебе      →  sleep → wake → sit  (встала, готова к задаче)
начали печатать         →  sleep → wake → sit  (услышала, что ты вернулся)
агент ждёт решения      →  sit                 (не спит, когда тебя ждут)
ошибка агента           →  sit                 (не спит, когда всё сломалось)
```

Порог в 10 секунд нужен потому, что полный цикл «лечь → поспать → встать»
занимает около 8,5 с: на коротком ходе кошка не успела бы лечь, как уже надо
вставать, и это выглядело бы как сбой, а не как поведение.

Два таймера не случайно разные:

- **10 с** — про ход агента. Считается от его начала.
- **60 с** — про тишину в сессии. Считается **от конца хода**, а не от
  последнего нажатия клавиши: иначе кошка засыпала бы, пока вы вдумчиво
  читаете длинный ответ, ничего не трогая. Минута — это «сессия открыта, но
  в ней давно ничего не происходит», а не «пользователь отошёл».
- Начало **нового хода** сбрасывает отсчёт тишины, поэтому после ответа
  кошка не засыпает мгновенно, «накопив» простой за время работы агента.

Признак «печатают» — непустой черновик в поле ввода, а не метка последнего
нажатия: будить нужно на факт «ты здесь», а отдельного вопроса «давно ли
печатали» у кошки нет.

Отдельного состояния «свернул окно» нет намеренно: если вкладка не активна
или окно свёрнуто, реакции всё равно никто не увидит, а таймеры продолжали бы
крутиться вхолостую.

Переходы `lie` и `wake` одноразовые — они замирают на последнем кадре, и
дальше кошку ведёт `advanceMood`: после `lie` она «доезжает» до `sleep`,
после `wake` возвращается в `sit`.

## Установка

```bash
pnpm install
pnpm build          # сборка в lib/
pnpm install-local  # доставить в профиль DSH
```

Затем **перезапустите DSH**: профиль читает свою копию пакета в
`node_modules`, поэтому одного `pnpm build` недостаточно — без
`install-local` в интерфейсе останется прежняя сборка.

`pnpm install-local` делает то же, что `dsh plugin add`: копирует пакет в
`node_modules` профиля и дописывает его в `dependencies` и
`dsh.profile.bundles`. Скрипт поддерживает `--profile <имя>` и `--dry-run`,
а манифест профиля сохраняет в `package.json.bak`.

Именно список `dsh.profile.bundles`, а не наличие пакета в `node_modules`,
определяет, что загрузится при старте.

Если CLI доступен в `PATH`, можно и штатно:

```bash
dsh plugin add Z:\projects\dsh-cat-pet
```

## Настройки

Панель в `settings.section` (`Настройки → Pet`):

- **Показывать питомца** — убрать котика, не удаляя плагин;
- **Размер** — `small` 96px · `medium` 128px · `large` 192px · `huge` 256px
  (по умолчанию `medium`);
- **Реагировать на статус агента** — выключенная кошка просто сидит;
- **Сбросить позицию** — вернуть в правый нижний угол.

Настройки и позиция живут в `localStorage`. Любое мусорное значение
приводит к дефолту, а не к исключению.

### Архитектура (сенсор → сигнал → оверлей)

```
conversation.composer.dock        shell.overlay
┌───────────────────────────┐     ┌──────────────────────────────┐
│ PetSensor (рисует null)   │     │ Cat                          │
│  useSession      → running│     │  useSyncExternalStore(сигнал)│
│                 + error   │     │   → signalToState → Player   │
│  useSessionStatus         │сигн.│  drag / clamp / позиция      │
│              → pendingKey │────►│  пауза на скрытой вкладке    │
│  useChat → tool-calls     │     │  без арта → placeholder      │
│  keyboard → черновик      │     │                              │
└───────────────────────────┘     └──────────────────────────────┘
```

Почему так: session-слот — единственное место, где видны факты хода (идут ли
инструменты, ждёт ли ход решения, есть ли текст в поле ввода), а оверлей не
получает ни пропсов слота, ни `ctx`. Хуки защищены `useOptional`: если версия
DSH не отдаёт хук, деградирует одна строка сигнала, а не весь плагин.

Сенсор не хранит «сколько прошло»: он кладёт в снапшот метки `runStartedAt` и
`runEndedAt`, а длительности считает `signalToState` в момент решения. Иначе
готовое число протухало бы между рендерами — снапшот обновляется только при
смене фактов, и кошка не легла бы, пока ход не завершится. По той же причине
`typing` уходит в сигнал свёрнутым в boolean: черновик меняется на каждое
нажатие, а котик должен перерисовываться только на факт «начал/перестал».

Хост-половина пустая намеренно: состояния читаются в браузере из клиентских
проекций DSH, поэтому дублировать их в хост-события и синхронизировать не
нужно. Хост остаётся точкой расширения, если позже понадобятся серверные
данные.

## Арт

Атлас лежит в `assets/` и **хранится в репозитории как готовый артефакт**:
`spritesheet.png` (4352×1024, сетка 17×4, ячейка 256×256, 68 кадров) и
`atlas.json`.

Скрипта сборки спрайт-листа в проекте нет: атлас нарезан заранее, и `pnpm
build` только вшивает готовый `assets/` в бандл. Это сделано намеренно —
генератор и исходные листы весили больше, чем весь остальной проект, а нужны
были лишь в момент перерисовки кота.

Чтобы собрать свой атлас, нарежьте кадры в сетку по требованиям ниже и
положите `spritesheet.png` + `atlas.json` в `assets/`, затем выполните
`pnpm sprites` (перевшить в `src/client/sprite-data.ts`) и `pnpm build`.
Единственное требование к самому рисунку: во всех четырёх состояниях кошка
должна смотреть в одну сторону.

### Требования к атласу

`atlas.json`:

```jsonc
{
  "image": "spritesheet.png",        // только имя файла, без путей
  "cell": { "w": 256, "h": 256 },    // размер кадра, целые px, ≤1024
  "grid": { "cols": 17, "rows": 4 }, // колонок и строк в листе
  "animations": {
    // [колонка, строка], 0-based, слева направо, сверху вниз
    "sit":   { "loop": true,  "fps": 6, "frames": [[0,0], [1,0]] },
    "lie":   { "loop": false, "fps": 6, "frames": [[0,1], [1,1]] },
    "sleep": { "loop": true,  "fps": 6, "frames": [[0,2], [1,2]] },
    "wake":  { "loop": false, "fps": 6, "frames": [[0,3], [1,3]] }
  }
}
```

| Поле | Обязательно | Смысл |
| --- | --- | --- |
| `image` | да | имя файла изображения в `assets/`, без путей и `..` |
| `cell.w/h` | да | размер кадра, целые положительные, ≤1024 |
| `grid.cols/rows` | да | размер сетки листа; кадры обязаны лежать внутри |
| `animations.<имя>.frames` | да | массив `[колонка, строка]`, 0-based |
| `animations.<имя>.loop` | нет (по умолчанию `true`) | `false` — один раз и замер на последнем кадре |
| `animations.<имя>.fps` | да, если нет `durations` | кадров в секунду, > 0 |
| `animations.<имя>.durations` | нет | длительности кадров в мс, длина = длине `frames`; приоритет над `fps` |
| `fallback` | нет | `{ состояние: "имя анимации" }` — чем закрыть состояния без своей анимации |

Обязательные анимации — все четыре состояния (`sit`, `lie`, `sleep`, `wake`).
Если чего-то нет, плагин не падает: отсутствующая анимация ругается в консоль
и играется через фолбэк (сначала `sit`, иначе первая найденная), а битый или
отсутствующий атлас уводит котика в canvas-заглушку.

Прочие требования к листу:

- сетка строго регулярная, кадры одинакового размера, без полей и отступов
  между кадрами (иначе дрожь при проигрывании);
- прозрачный фон, чистая альфа, без ореолов по краям силуэта;
- кот должен читаться и на светлой, и на тёмной теме — обводка, тень или
  контрастный силуэт;
- лист вшивается в бандл как `data:URL`, поэтому его размер прямо влияет на
  размер `lib/client.js` (примерно ×1.37). Текущий лист — 78 КБ.

Кадр — это размер ячейки, а не кота: в ячейке 256×256 кошка занимает около
108×150 px. Уменьшение безопасно, увеличение даёт мыло — поэтому исходники
держатся в ×4.

## Слоты: что проверено на живом DSH

| Слот | Кардинальность | Подтверждение |
| --- | --- | --- |
| `shell.overlay` | список, слой во весь кадр | `dshmarket` (установлен локально) и `Cheva1234/dsh-chibi-pet` |
| `conversation.composer.dock` | список | есть в сгенерированном каталоге слотов DSH |
| `settings.section` | список | `dshmarket` (`id: 'market'`) и `dsh-our-free-model` |

Важно: `shell.overlay` и `settings.section` **отсутствуют** в
`slot-catalog.ts` — это каталог слотов, объявленных *фичевыми* пакетами. Оба
слота объявляет сам каркас, поэтому единственный надёжный способ убедиться в
их существовании — посмотреть, кто их уже занимает.

Локаль (сверено с `dshmarket` и `dsh-our-free-model`):

```js
ctx.effect(() => ctx.locale.register(NS, { ru, en }), 'cat-pet: dictionaries')
const t = ctx.locale.bind(NS)
```

`t` доставляется в компонент через `inject` регистрации, а не как пропс слота.
Словари — плоская карта «ключ → строка», вложенность не поддерживается.

## Чего избегаем (реальные баги чужих плагинов)

- **Постоянный rAF-цикл** при 60 fps под кадры по 300–700 мс → проседает вся
  страница ([dsh-pet #17](https://github.com/zhu1090093659/dsh-pet/issues/17)).
  Решение: проигрывание по таймингам через `setTimeout`, пауза при скрытой
  вкладке, `prefers-reduced-motion`.
- **Неограниченный кэш decode** — 93 МБ на 372 кадра (dsh-pet #19). У нас этой
  проблемы нет по конструкции: один лист грузится ОДНИМ `Image`, отдельных
  битмап на кадр не создаётся.
- **Аллокации в кадре** и чтение layout каждые 40 мс
  (dsh-whale-girl-live2d #3).
- **Нет clamp позиции** → питомец уезжает за экран после ресайза
  (dsh-whale-girl-live2d #13).
- **Поллинг вместо событий.** У нас нет ни поллинга, ни своего эндпоинта:
  состояния берутся из клиентских проекций DSH.
- **Инжект в index.html** вместо слотов — вторая drag-система и хрупкость.
- **Полный pointer-events слоя** — перехват скролла и колеса. У нас
  `pointer-events: auto` стоит только на самом канвасе котика.
- **Один монолит на 130–160 КБ** без сборки; у нас tsdown, strict-типы, тесты.
- **Забытая локаль** (dsh-pet #11: русский UI был китайским).
- **Съезжающий таймлайн при разных `durations`** — свой баг, найденный
  ревизией: `startedAt` сдвигался на длительность ПРЕДЫДУЩЕГО кадра, поэтому
  при `durations: [500, 100, 100]` время расходилось с реальным. Логика
  вынесена в `src/shared/timeline.ts` и покрыта регрессионным тестом.
