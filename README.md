# dsh-cat-pet

Анимированный котик-компаньон для веб-интерфейса
[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness).

Кошка живёт поверх интерфейса: её можно перетаскивать, она помнит позицию и
реагирует на то, чем занят агент.

## Поведение

| Анимация | Когда |
| --- | --- |
| `sit` | по умолчанию: короткий ход, ход завершён, ожидание решения, ошибка, идёт печать |
| `lie` | переход `sit → sleep`, один раз |
| `sleep` | агент думает дольше 10 секунд **или** в сессии больше минуты тишины |
| `wake` | переход `sleep → sit`, один раз |

Два порога намеренно разные:

- **10 с** — про ход агента, считается от его начала. Полный цикл «лечь →
  поспать → встать» занимает ~8,5 с, поэтому на коротком ходе кошка не успела
  бы лечь, как уже надо вставать.
- **60 с** — про тишину в сессии, считается **от конца хода**, а не от
  последнего нажатия клавиши: иначе кошка засыпала бы, пока вы читаете
  длинный ответ. Новый ход сбрасывает отсчёт.

Кошка не спит, когда агент ждёт решения или упал с ошибкой. Отдельного
состояния «свернул окно» нет: реакции всё равно никто не увидит, а таймеры
крутились бы вхолостую.

## Установка

```bash
pnpm install
pnpm build          # сборка в lib/
pnpm install-local  # доставить в профиль DSH
```

Затем **перезапустите DSH**. Одного `pnpm build` недостаточно: профиль читает
свою копию пакета в `node_modules`, и без `install-local` в интерфейсе
останется прежняя сборка.

`pnpm install-local` делает то же, что `dsh plugin add`: копирует пакет в
профиль и дописывает его в `dependencies` и `dsh.profile.bundles` —
именно этот список, а не наличие пакета в `node_modules`, определяет, что
загрузится при старте. Поддерживает `--profile <имя>` и `--dry-run`.

Если CLI доступен в `PATH`, можно штатно:

```bash
dsh plugin add <путь-к-репозиторию>
```

## Настройки

Панель в `settings.section` (`Настройки → Pet`):

- **Показывать питомца** — убрать котика, не удаляя плагин;
- **Размер** — `small` 96px · `medium` 128px · `large` 192px · `huge` 256px
  (по умолчанию `medium`);
- **Реагировать на статус агента** — выключенная кошка просто сидит;
- **Сбросить позицию** — вернуть в правый нижний угол.

Настройки и позиция живут в `localStorage`; мусорное значение приводит к
дефолту, а не к исключению.

## Арт

`assets/spritesheet.png` (4352×1024, сетка 17×4, ячейка 256×256, 68 кадров) и
`assets/atlas.json` — **готовый артефакт репозитория**. Генератора спрайт-листа
нет: `pnpm build` только вшивает готовый `assets/` в бандл.

Чтобы подставить свой атлас, нарежьте кадры в регулярную сетку и положите
`spritesheet.png` + `atlas.json` в `assets/`, затем:

```bash
pnpm sprites   # перевшить assets/ в src/client/sprite-data.ts
pnpm build
```

Требования к листу:

- сетка строго регулярная, кадры одного размера, без полей и отступов между
  ними (иначе дрожь при проигрывании);
- прозрачный фон, чистая альфа, без ореолов по краям силуэта;
- кошка должна читаться и на светлой, и на тёмной теме;
- во всех четырёх состояниях кошка смотрит в одну сторону.

`atlas.json`:

```jsonc
{
  "image": "spritesheet.png",        // только имя файла, без путей
  "cell": { "w": 256, "h": 256 },    // размер кадра, целые px, ≤1024
  "grid": { "cols": 17, "rows": 4 }, // колонок и строк в листе
  "animations": {
    // [колонка, строка], 0-based, слева направо, сверху вниз
    "sit":   { "loop": true,  "fps": 6, "frames": [[0,0], [1,0]] },
    "lie":   { "loop": false, "fps": 6, "frames": [[0,1], [1,1]] },
    "sleep": { "loop": true,  "fps": 6, "frames": [[0,2], [1,2]] },
    "wake":  { "loop": false, "fps": 6, "frames": [[0,3], [1,3]] }
  }
}
```

| Поле | Обязательно | Смысл |
| --- | --- | --- |
| `image` | да | имя файла в `assets/`, без путей и `..` |
| `cell.w/h` | да | размер кадра, целые положительные, ≤1024 |
| `grid.cols/rows` | да | размер сетки; кадры обязаны лежать внутри |
| `frames` | да | массив `[колонка, строка]`, 0-based |
| `loop` | нет (`true`) | `false` — один раз и замер на последнем кадре |
| `fps` | да, если нет `durations` | кадров в секунду, > 0 |
| `durations` | нет | длительности кадров в мс, приоритет над `fps` |
| `fallback` | нет | `{ состояние: "имя анимации" }` |

Обязательны все четыре состояния. Если чего-то нет, плагин не падает:
отсутствующая анимация ругается в консоль и играется через фолбэк (сначала
`sit`, иначе первая найденная), а битый атлас уводит котика в canvas-заглушку.

Кадр — это размер ячейки, а не кота: в ячейке 256×256 кошка занимает около
108×150 px. Лист вшивается в бандл как `data:URL`, поэтому добавляет к
`lib/client.js` примерно ×1.33 от своего размера (текущий лист — 78 КБ).

### Структура

```
package.json        dsh-блок: bundle.patch + client.platform=web
cordis.patch.yml    insert: монтирование хост-половины
src/shared/         чистые функции: состояния, таймлайн, позиция, настройки, локаль
src/host/           apply(ctx) — пустая подстраховка загрузчика
src/client/         слоты: sensor (факты сессии) → signal → cat (canvas, drag)
src/client/sprite-data.ts   ГЕНЕРИРУЕТСЯ build-atlas.mjs
assets/             spritesheet.png + atlas.json (в git)
tools/              сборка атласа, три приёмки, install-local
tests/              atlas, timeline, prefs, locales, signal+mood, position
```

Как это связано: session-слот — единственное место, где видны факты хода
(идут ли инструменты, ждёт ли ход решения, есть ли текст в поле ввода), а
оверлей не получает ни пропсов слота, ни `ctx`. Поэтому сенсор публикует факты
в модульный сигнал, а оверлей читает его через `useSyncExternalStore`.

Сенсор не хранит «сколько прошло»: он кладёт в снапшот метки `runStartedAt` и
`runEndedAt`, а длительности считает `signalToState` в момент решения — иначе
готовое число протухало бы между рендерами. `typing` уходит в сигнал свёрнутым
в boolean: черновик меняется на каждое нажатие, а котик должен
перерисовываться только на факт «начал/перестал».

Хост-половина пустая намеренно: состояния читаются в браузере из клиентских
проекций DSH, дублировать их в хост-события незачем.
